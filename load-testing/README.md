# Тестирование производительности Search API

Этот проект настроен для проведения специализированного тестирования производительности метода поиска пользователей с анализом влияния индексов базы данных на латентность и пропускную способность.

## 🎯 Цель тестирования

Провести сравнительный анализ производительности метода `GET /api/v1/user/search` **до** и **после** добавления индексов базы данных для демонстрации влияния оптимизации на:
- **Latency** (задержка отклика)
- **Throughput** (пропускная способность)

## 🔧 Архитектура тестирования

- **Apache JMeter** - генерация нагрузки на Search API
- **InfluxDB** - хранение временных рядов метрик производительности
- **Grafana** - визуализация результатов в реальном времени
- **PostgreSQL** - тестируемая база данных

## 🚀 Быстрый старт

### Этап 1: Тестирование БЕЗ индексов

```bash
# Запуск тестирования без индексов
./load-testing/run-search-performance-test.sh
```

Этот скрипт:
1. Запускает всю инфраструктуру (приложение, БД, InfluxDB, Grafana)
2. Генерирует 1,000,000 тестовых пользователей
3. Проводит тестирование с нагрузкой: **1, 10, 100, 1000** потоков
4. Каждый тест выполняет **50 итераций**
5. Сохраняет результаты в InfluxDB и файлы

### Этап 2: Добавление индексов

```bash
# Добавление индексов для оптимизации поиска
./load-testing/add-indexes.sh
```

Создает следующие индексы:
- `idx_users_first_name` - по полю first_name
- `idx_users_last_name` - по полю last_name  
- `idx_users_names` - составной индекс (first_name, last_name)

### Этап 3: Тестирование С индексами

```bash
# Запуск тестирования с индексами
./load-testing/run-search-after-index.sh
```

Проводит идентичное тестирование с теми же параметрами нагрузки.

## 📊 Анализ результатов

### Grafana Dashboard

Откройте специализированный дашборд: http://localhost:3000/d/search-performance

#### Ключевые метрики:

1. **🚀 Current Throughput (RPS)** - текущая пропускная способность
2. **⏱️ Current Response Time** - текущее время отклика
3. **🎯 95th Percentile Latency** - латентность 95-го перцентиля
4. **❌ Error Rate** - процент ошибок

#### Графики:

- **📈 Throughput Over Time** - пропускная способность во времени
- **⏱️ Response Time Distribution** - распределение времени отклика
- **📊 Load Profile** - профиль нагрузки (активные потоки)
- **🔥 Performance Correlation** - корреляция производительности
- **📋 Performance Summary** - сводная таблица по уровням нагрузки

### Ожидаемые результаты

#### БЕЗ индексов:
- **Высокая латентность** при увеличении нагрузки
- **Низкая пропускная способность** на высоких нагрузках
- **Возможные ошибки** при 1000 потоках

#### С индексами:
- **Стабильно низкая латентность** 
- **Высокая пропускная способность**
- **Отсутствие ошибок** даже при максимальной нагрузке

## 🔧 Конфигурация тестирования

### Параметры нагрузки:
- **Потоки**: 1, 10, 100, 1000 виртуальных пользователей
- **Длительность**: 120 секунд каждый тест  
- **Нарастание**: 10 секунд на достижение целевого числа потоков
- **Пауза между тестами**: 30 секунд

### Тестовые данные:
- **1,000,000** пользователей в базе данных
- **24** различных комбинации имени/фамилии для поиска
- **Циклическое** использование параметров поиска

## 🛠️ Кастомизация

### Изменение параметров нагрузки:

Отредактируйте массив `THREAD_COUNTS` в скриптах:
```bash
THREAD_COUNTS=(1 10 100 1000)  # Ваши значения
TEST_DURATION=120              # Длительность в секундах
```

### Изменение параметров поиска:

Отредактируйте файл `search_params.csv`:
```csv
first_name,last_name
Ваше,Имя
Другое,Имя
```

### Дополнительные индексы:

Добавьте в `add-indexes.sh`:
```sql
CREATE INDEX CONCURRENTLY idx_custom ON users (custom_field);
```

## ⚡ Команды для быстрого анализа

```bash
# Просмотр текущих индексов
docker-compose exec db psql -U postgres -d social_network -c \
  "SELECT indexname, tablename FROM pg_indexes WHERE tablename = 'users';"

# Анализ размеров индексов  
docker-compose exec db psql -U postgres -d social_network -c \
  "SELECT schemaname, tablename, indexname, 
   pg_size_pretty(pg_relation_size(indexrelid)) as size
   FROM pg_stat_user_indexes WHERE tablename = 'users';"

# Очистка результатов
rm -rf load-testing/results/*

# Остановка всех сервисов
docker-compose down
```

## 🔍 Решение проблем

### База данных не отвечает:
```bash

docker-compose restart db
```

### JMeter не может подключиться:
```bash
docker-compose ps
curl http://localhost:8000/api/v1/user/search?first_name=Test&last_name=User
```

### Grafana не показывает данные:
```bash

curl "http://localhost:8086/query?q=SHOW DATABASES"
```
